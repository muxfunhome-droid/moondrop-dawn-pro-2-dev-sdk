# moondrop_rew

Реверс-инжиниринг прошивки USB-ЦАПа **Moondrop DAWN PRO2** (SPACETOUCH SPV4040, ядро Andes RISC-V) и инструменты для её модификации:
эмулятор, прошивальщик, смена цветов светодиода и **SDK для написания своих программ на C**.

## Что уже работает (проверено на железе)

- 🔌 **WebHID-прошивальщик** в браузере (`web/spv_flasher.html`): вход в загрузчик, запись, проверка чтением, дамп flash.
- 🎨 **Свои цвета светодиода** во всех режимах (`tools/spv_led_colors.py`): обычный режим, режим эквалайзера, мигание, предел громкости.
  Поправлена полярность ШИМ и фаза «погашено» при мигании (LED с общим анодом).
- 🧑‍💻 **SDK для C** (`sdk/`): `app_init()` / `app_loop()` внутри прошивки, таймеры, управление светодиодом, журнал.
  Пример: радуга на LED (`sdk/examples/rainbow`) работает на реальном устройстве.
- 🔊 **Свой звук** (`sdk/examples/bubble`): программа встраивается в аудио-тракт (USB → EQ → ЦАП), добавляет эффект «warm»
  (бас, кроссфид для наушников, мягкий ограничитель) и **мягкий булькающий звук на кнопках громкости «+»/«−»**.
  Двойной клик «−» включает/выключает эффект. Проверено на железе.
- 🧪 **Эмулятор** RV32IMAC + F + Andes (AndeStar V5, DSP): прошивка загружается до главного цикла, перед прошивкой образ можно проверить.

## Быстрый старт

Нужны: Linux, Python 3, `gcc-riscv64-unknown-elf` (для SDK; Debian/Ubuntu: `sudo apt install gcc-riscv64-unknown-elf`), Chrome/Edge для прошивальщика.

```sh
git clone https://github.com/muxfunhome-droid/moondrop-dawn-pro-2-dev-sdk && cd moondrop-dawn-pro-2-dev-sdk

# 1. положите СВОЙ образ в firmware/ (сборка «Nov 17 2025 13:50:18»)
cp ~/path/to/firmware.bin firmware/firmware.bin
python3 tools/spv_fw_tool.py info firmware/firmware.bin       # разбор и проверка checksum

# 2. права доступа для браузера (один раз), затем переподключите ЦАП
sudo cp udev/70-moondrop-dac.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo udevadm trigger

# 3. цветной образ: обычный режим зелёный, режим EQ и мигание фиолетовые
scripts/build_custom.sh firmware/firmware.bin build/fw_custom2.bin

# 4. (необязательно) своя программа на C поверх него
scripts/build_app.sh rainbow build/fw_custom2.bin build/fw_rainbow.bin
scripts/build_app.sh bubble  build/fw_custom2.bin build/fw_bubble.bin    # звук + бульки на кнопках

# 5. открыть web/spv_flasher.html в Chrome, выбрать образ, «Перевести в загрузчик» → «Подключить загрузчик» → «Прошить»
```

Перед первой прошивкой снимите **дамп flash** кнопкой в прошивальщике и сохраните его. Первой прошивайте непатченый оригинал
(проверка цепочки), потом патченые образы.

## Что известно про устройство

| | |
|---|---|
| USB | рабочий режим `35d8:011d`, загрузчик `0666:0888` («USB20»); вход в загрузчик HID-отчётом `[75, 1, 255]` |
| Ядро | Andes RISC-V (RV32IMAC + F + Andes-расширения), 360 МГц |
| Память | код исполняется из SPI-flash (XIP `0x48000000`) + ITCM-копия части кода по адресу 0; RAM `0x100000…0x140000` |
| LED | RGB на ШИМ, пины R3 / G33 / B5, **общий анод** (duty 0 = горит) |
| «Обычный режим» | EQ-пресет 8 (заводской); «режим эквалайзера» = пресет ≠ 8 |
| Привязка к чипу | ID кристалла XOR `"Ttg?Tech"` сверяется с ключом в flash `0x3e000` (в образе его нет) |

## Риски

- Работает только сборка прошивки **«Nov 17 2025 13:50:18»**. Скрипты проверяют дату и исходные байты и отказываются работать с другим образом.
- Нельзя вешать `app_loop()` в своей программе: через главный цикл идёт HID-команда входа в загрузчик. Держите наготове дамп и проверенный образ.
- Дамп flash содержит уникальный ключ привязки к вашему чипу и конфигурацию USB — не публикуйте его.
- Загрузчик восстановим: неудачная заливка оставляет устройство в режиме `0666:0888`, откуда можно залить рабочий образ. Но гарантий нет.

## Идеи

Кнопки/ручка через АЦП, управление LED с компьютера по HID, индикатор громкости или частоты дискретизации, режимы подсветки,
разбор HID-команд вендора и конфигурации USB (`0x38000`), модель USB-хоста в эмуляторе. Подробнее в `docs/ARCHITECTURE.md` §9.
