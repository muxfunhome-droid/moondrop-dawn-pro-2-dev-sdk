# calc — калькулятор, который считает внутри USB-ЦАПа

**Язык:** [English](README.md) · Русский

Чисто по рофлу: ПК отправляет выражение, **RISC-V внутри Moondrop DAWN PRO 2** его разбирает и считает,
ответ возвращается по USB. Звук не трогается, ЦАП играет как обычно. После каждого вычисления LED на 150 мс голубой.

Настоящий вывод с устройства:
```
$ sdk/examples/calc/host/calc "(2+3)*-2^3 / 7"
= -5.71428571428571
  посчитано на RISC-V в ЦАПе: 16510 тактов (45.9 мкс), вычисление №6, USB туда-обратно 15.9 мс
```

## Сборка
```sh
scripts/build_app.sh calc build/fw_custom2.bin build/fw_calc.bin   # прошивка, с проверкой в эмуляторе
python3 -I sdk/examples/calc/test_emu.py                           # 19 выражений против Python, ошибки, заводские команды
make -C sdk/examples/calc/host                                     # программа для ПК (Linux, без зависимостей)
```
`build/fw_calc.bin` прошивается через `web/spv_flasher.html`.

## Использование (Linux)
```sh
sdk/examples/calc/host/calc "2+2*2"          # одно выражение
sdk/examples/calc/host/calc 2 + 2 '*' 2      # аргументы склеиваются (* в кавычках, иначе шелл раскроет)
sdk/examples/calc/host/calc                  # интерактивный режим
```
Операции: `+ - * / % ^ ( )`, `sqrt(x)`, `pi`, `e`, числа вида `1.5e3`. `^` — только целые степени, правоассоциативно
(`2^3^2 = 512`), унарный минус слабее степени (`-3^2 = -9`). Считается в `double` (софт-float из libgcc: в ядре только single).
Устройство ищется само (`/sys/class/hidraw`, VID:PID `35d8:011d` + report ID 75 в дескрипторе), вручную: `-d /dev/hidrawN`.
Доступ к `/dev/hidraw*` даёт udev-правило из `udev/`.

## Как устроено
- **Канал.** Vendor HID-отчёт 75 (тот же, через который флешер шлёт «войти в загрузчик»), 64 байта.
  Запрос `[75, 0xCA, seq, len, выражение…]`, ответ `[75, 0xCA, seq, status, errpos, 0,0,0, double @8, такты u32 @16, счётчик u32 @20]`.
- **Приём в прошивке.** USB-прерывание (`0x748c`, или `SET_REPORT` по control) кладёт отчёт в буфер `msg = 0x106554 {state, buf}`
  и ставит `state = 2`. Главный цикл зовёт обработчик `0x8d84(ctx 0x121ec0, msg)`.
- **Перехват.** `app_init()` через `spv_ram_redirect()` направляет `0x8d84` в `calc_hid()`. Отчёты с байтом `0xCA` считает он,
  остальные (включая `[75,1,255]` — вход в загрузчик) уходят в заводской код с `0x8d94`. Перепрошивка работает как раньше.
- **Ответ.** В тот же буфер, отправка заводской `0x8418(ctx, buf, 64)` — так же отвечает и сама прошивка.
  Отправка копирует данные в FIFO эндпоинта сразу (`0x7f68`).
- **Такты** — `mcycle` до/после разбора, на 360 МГц. В эмуляторе число тактов бессмысленное (там время ускорено).

Статус: ✅ работает на железе. В эмуляторе проверено `test_emu.py`.
