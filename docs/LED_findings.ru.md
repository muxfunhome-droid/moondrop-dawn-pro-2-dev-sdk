# Светодиод в прошивке SPV-ЦАПа — отчёт (v2, по результатам эмуляции)

**Язык:** [English](LED_findings.md) · Русский


Цель: найти, как задаётся цвет и яркость LED, и как их поменять перепрошивкой.
Итог: **логика найдена полностью и проверена в эмуляторе**. Предыдущая версия отчёта
(«цифровой LED на GPIO 0x20005000, фиксированная яркость, 0x21010000 = IOMUX») была неверной.

## Инструменты (в этой папке)
| Файл | Что делает |
|------|-----------|
| `spv_emu.py` | эмулятор RV32IMAC + Zicsr + F + AndeStar V5 (bbc/bbs/beqc/bnec/bfos/bfoz/lea/*gp) + Andes DSP (minw/maxw/add64/wexti/smar64/maddr32/…), лог MMIO, детектор циклов опроса, ускорение mcycle, встроенный дизассемблер `dis()` |
| `led_run.py` | обвязка: заглушки boot-ROM (memcpy/memset/SPI-flash), заводской ключ, журнал GPIO |
| `led_probe.py` | сценарии LED: выставляет EQ-пресет / событие / флаг LED и печатает записи в ШИМ и пады |

```
python3 led_run.py   firmware.bin 3000000   # загрузка до главного цикла + лог периферии
python3 led_probe.py firmware.bin           # сценарии светодиода
```

## Что пришлось сэмулировать, чтобы прошивка загрузилась
- **Boot-ROM `0x80000`**: `0x80318` memcpy, `0x80410` memset, `0x8225e` чтение SPI-flash,
  `0x8213c` стирание, `0x82200` запись, `0x82356/0x8236e` начало/конец операции. Через указатель `0x80080` вызывается printf.
- **Код в RAM**: загрузчик копирует `0x9baa` байт с flash `0x48010a60` по адресу `0x0`.
  Адрес RAM `X` ↔ смещение в файле `0x10a60 + X`. *Из-за этого прошлый статический анализ и не находил вызовов драйверов.*
- **Привязка к чипу**: ID кристалла (`0x20160028/2c`) XOR `"Ttg?Tech"` сравнивается с 8 байтами
  на flash `0x3e000`, записанными на заводе. В образе их нет, в эмуляторе ключ подставляется.
- Контроллер прерываний: PLIC Andes по `0x10000000` (claim/complete по `0x10200004`), векторный режим, таблица по `0x48001500`.
- Главный цикл: суперцикл `0x360`, без RTOS. Обработка аудио идёт только после USB `SET_CONFIGURATION` (`[0x106538] ≥ 2`).

## Аппаратная часть LED (RGB, ШИМ)
| Цвет (по API прошивки) | Пин | Пад-регистр | Канал ШИМ |
|------|-----|-----------|-----------|
| R | 3  | `0x2011000c` | ch3 → `0x2010000c` |
| G | 33 | `0x20110084` | ch1 → `0x20100004` |
| B | 5  | `0x20110014` | ch5 → `0x20100014` |

- `pwm_set(pin, en, duty)` = `0x48004184`: пад ← `9` (функция ШИМ), канал ← `(duty<<16) | 0xff00` (+бит 0 = enable). **8-битный ШИМ, 0..255.**
- `led_set_rgb(r, g, b, on, brightness)` = `0x48004288`: `duty = цвет × brightness / 255.0`. При `on = 0` все каналы в 0.
- Пад `0x210` / `0x10` = вывод не в функции ШИМ (светодиод выключен).
- `0x21010000` — это **АЦП** (ручки/кнопки), а не IOMUX. `0x20005000` (GPIO) трогается только при подготовке ко сну.

## Логика цвета
Главный цикл (`0x360`): если LED включён в настройках (`st[15]` = байт `0x11cb1f`, сохраняется во flash), вызывается
`led_task` (`0x5fc`) по событию `[0x1064b8]` = `{u8 event; u8 blink; u16 half; u16 period}`. Если LED выключен, все пады ← `0x210`.

| Событие | Что горит | Код |
|---|---|---|
| 0 (обычное состояние), EQ-пресет ≠ 8 | **(R0, G220, B255)**, яркость 255 → голубой | `0x72c` |
| 0, EQ-пресет = 8 (заводское значение в настройках) | ШИМ не включается: R ← `0x10`, G/B ← `0x210` (выключено) | `0x75c` |
| 1, 2 | белый (255,255,255), мигание 500/500. Событие 2 — **громкость достигла предела** | `0x624` |
| 3, 4, 5 | фиолетовый (102,0,255) | `0x648` |
| 6 | красный (255,0,0) | `0x66c` |
| 7 → 8 | красный, затем зелёный (0,255,0) | `0x68c`/`0x6c4` |
| 9 | синий (0,0,255) | `0x6fc` |

Жёлтого цвета (R+G) в этой прошивке нет ни в одном вызове `led_set_rgb` (всего 9 мест вызова).
Описание «красный/жёлтый/белый» из README относится не к этому образу.

## Как поменять цвет и яркость обычного состояния (проверено в эмуляторе)
Инструкции в `0x734..0x742` (RAM), смещения в файле:

| Смещение | Сейчас | Смысл | Формат |
|---|---|---|---|
| `0x11194` | `1307f00f` | `addi a4,zero,255` — **яркость** | 4 Б, 0..255 (до 2047) |
| `0x1119a` | `1306f00f` | `addi a2,zero,255` — **B** | 4 Б |
| `0x1119e` | `9305c00d` | `addi a1,zero,220` — **G** | 4 Б |
| `0x111a2` | `0145` | `c.li a0,0` — **R** | 2 Б, только 0..31 |

Кодировка: `addi rd,zero,imm` = `(imm<<20) | (rd<<7) | 0x13`, little-endian; a1 = 11, a2 = 12, a4 = 14.
Пример (зелёный, проверен в `led_probe`: ch1 = 255, ch3 = ch5 = 0):
```
python3 spv_fw_tool.py patch firmware.bin -o p1.bin       --offset 0x1119a --bytes 13060000   # B=0
python3 spv_fw_tool.py patch p1.bin       -o fw_green.bin --offset 0x1119e --bytes 9305f00f   # G=255
```
Для R > 31 нужен 4-байтный `addi`, а места всего 2 байта. Придётся переделывать фрагмент: например, поменять
регистры местами или прыгнуть в патч-область.

## Что остаётся непроверенным (нужно устройство)
1. **Какой физический цвет на каком пине.** Имена R/G/B взяты из самих вызовов (вендор передаёт
   (255,0,0) как «красный», (102,0,255) как «фиолетовый»), но разводку платы из прошивки не узнать.
2. **Полярность.** Если LED с общим анодом, то `duty = 255` может означать «погашен».
3. **Какой EQ-пресет сохранён на твоём устройстве.** При пресете 8 обычное состояние не использует ШИМ-цвет вовсе.
4. Эмуляция USB-хоста не делалась: состояние «сконфигурировано» и события выставлялись в памяти напрямую.

## Результат на железе (2026-11-08): полярность ШИМ ИНВЕРТИРОВАНА
`fw_green.bin` (normal = 0,255,0) на устройстве светился **фиолетовым**. Это ровно «R и B горят, G погашен»,
т.е. LED с общим анодом: duty 0 = полный свет, duty 255 = погашен. Исправление — `spv_led_colors.py --invert on`
(3 × `bfoz a2,a2,15,0` в `led_set_rgb` @0x48004288 → `xori a2,a2,255`), цвета после этого задаются «как есть».
Вызовов `led_set_rgb` с `on=0` в прошивке нет (все 9 мест передают `a3=1`), ветка «все каналы в 0» мертва.
Фаза «погашено» при мигании использует пады = 0x10 (не ШИМ) — на железе после инверсии не проверялось.
Образ: `fw_custom.bin` = `--invert on --set all=160,0,255 --set normal=0,255,0` (normal зелёный, остальное фиолетовое).

## Уточнение (2026-11-08, вторая итерация на железе)
- «Обычный режим» устройства = **EQ-пресет 8** (заводской). Там ШИМ-цвет не включается вообще: пад R ← 0x10 (красный горит),
  G/B ← 0x210 (погашены). Поэтому цвет `normal` (пресет ≠ 8, «кастомная настройка/эквализация») в обычном режиме не виден.
  Новый «сайт» `normal8` (RAM 0x75c) вместо этого вызывает `led_set_rgb`.
- Пад **0x10 = светодиод ГОРИТ**, 0x210 = погашен. Фаза «погашено» мигания (5 блоков по 16 Б: 0x48003014/3050/30a0/30f4/3144)
  ставила все три пада в 0x10 → белая вспышка между цветами. `--blink-off dark` заменяет на 0x210 (общая заглушка за стабами).
- ШИМ: duty 0 = канал горит (общий анод); `--invert on` это компенсирует.
- Образ: `fw_custom2.bin` = `--invert on --blink-off dark --set all=160,0,255 --set normal8=0,255,0`
  (обычный режим зелёный; пресет ≠ 8 и все события/мигание фиолетовые).
