# SPV DAC — патчер и прошивальщик

Формат прошивки и протокол загрузчика восстановлены из веб-приложения
`hub.moondroplab.tech` (бандл `assets/index-*.js`). Устройство — ЦАП на ядре
RISC-V с контейнером «SPV APP Tag» (magic `SPV@`). Твои `firmware.bin` и
`firmware_prevc.bin` — валидные образы этого формата (проверка проходит).

## Файлы
- `spv_flasher.html` — прошивальщик по WebHID (Chrome/Edge). Повторяет протокол хаба байт-в-байт.
- `spv_fw_tool.py`   — разбор / проверка / патч контейнера с пересчётом checksum.

## Протокол (кратко)
- Транспорт: WebHID, output-репорт `reportId=0`, всё сообщение — одним репортом с zero-паддингом.
- Кадр: `magic(4)=0x58585542 | cmd(2)=OP|CMD<<8 | seq(1) | flag(1) | len(2) | crc32(4 по первым 10Б)` + `[content | crc32(content)]`. CRC32 — стандартный IEEE.
- Последовательность прошивки: `handshake(0x0110)` → для каждой секции `setWriteArea(0x0120, addr,len,slice=256)` → чанки по 256Б `writeData(0x0121)` → `endReset(0x0124)`.
- Вход в загрузчик из рабочего режима: обычная команда `[OP=1, CMD=255]` на `reportId` устройства (у Moondrop = 75). После этого девайс переподключается как **VID 0x0666 / PID 0x0888** («USB20») — это и есть загрузчик.

## Как прошивать
1. Открой `spv_flasher.html` в Chrome/Edge.
2. Выбери `.bin` — страница разберёт секции и проверит checksum.
3. Если устройство в обычном режиме — «Перевести в загрузчик» (подбери reportId).
4. «Подключить загрузчик (0x0666:0x0888)» → «Прошить». Галка «проверять чтением» сверяет записанное.

> Сначала сними дамп оригинала с устройства и сохрани. Загрузчик восстановим:
> неудачная заливка оставляет девайс в режиме 0x0666:0x0888, откуда заливается рабочий образ.

## Патч (для экспериментов со светодиодом)
checksum секции = сумма байт её данных (собственное поле checksum = 0, если внутри диапазона).
`spv_fw_tool.py` пересчитывает её автоматически — патченый образ остаётся валидным.

```
python3 spv_fw_tool.py info  firmware.bin
python3 spv_fw_tool.py patch firmware.bin -o fw_new.bin --offset 0x89d6 --bytes 2f0a03b4
python3 spv_fw_tool.py fixcrc fw_edited.bin -o fw_fixed.bin   # после ручной правки в hex-редакторе
```

## Про светодиод
**Устарело. Актуально в `LED_findings.md` и `ARCHITECTURE.md`.** Коротко: RGB на ШИМ `0x20100000`
(пины 3/33/5), а не `0x21010000` (это АЦП). Цвета всех режимов меняются через `spv_led_colors.py`.

## Дамп и вход в загрузчик (обновлено)
- Кнопка «Снять дамп flash» (после подключения загрузчика) читает `0x48000000…+0x40000` и сохраняет `.bin`.
  В дамп попадают области, которых нет в образе: конфиг USB `0x38000`, настройки `0x39bc0`, ключ чипа `0x3e000`.
- «Перевести в загрузчик» показывает все HID-устройства: VID ЦАПа в рабочем режиме лежит в конфиге flash
  и в образе не виден. Прошивка ждёт отчёт `[75, 1, 255]` (reportId 75), это совпадает с тем, что шлёт кнопка.
