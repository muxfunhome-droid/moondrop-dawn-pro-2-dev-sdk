## 2. Контейнер и разметка SPI-flash

Заголовок (`spv_fw_tool.py`, docstring): `off 0` reset-вектор `j 0xa4` · `+4` "SPV@" · `+8` entry `0x48001000` ·
`+0xC` userFlag "AMAO" · `+0x14/0x18` указатели на строки даты/времени · `+0x1C` число секций ·
`+0x20` директория `{name[4], addr, size, checksum}` × N.
Checksum секции = 32-битная сумма байт данных секции; собственное поле checksum считается нулём. ✅

| Смещение flash | Что | В `.bin`? |
|---|---|---|
| `0x00000–0x20ad4` | секция **CPU** (весь код и данные) | да |
| `0x20ad4–0x37000` | пусто (в файле нули). **Область патчей**: `spv_led_colors.py` занимает `0x20ae0–0x20b94` и расширяет CPU | да |
| `0x37000` | секция **EXT** (0x47 Б) ❓ назначение | да |
| `0x38000` | блок конфигурации устройства, 0xbc0 Б, читается при старте (`0x4e18`). 🟡 там USB VID/PID/строки: статического дескриптора в образе нет | **нет** |
| `0x39bc0` | **UI-настройки** (40 Б, версия = 2), `flash_save_ui_param` | **нет** |
| `0x3e000` | **ключ привязки к чипу** (8 Б), уникален для экземпляра | **нет** |
| `0x4c000000` | при старте проверяется "SPV@" по `0x4c000004` (второй образ / внешняя flash?) ❓ | — |

> ⚠️ `0x38000`, `0x39bc0` и `0x3e000` есть только на устройстве. Флэшер пишет лишь секции из `.bin`,
> поэтому эти области переживают перепрошивку (если загрузчик не стирает чип целиком ❓).
> **Перед любыми экспериментами снимите дамп 0x48000000…0x48040000** (кнопка в `spv_flasher.html`).

## 3. Процессор и память

Ядро Andes RV32 (AndeStar V5): **RV32IMAC + F + Zicsr**, Andes-расширения: Performance (`bbc/bbs`,
`beqc/bnec`, `bfos/bfoz`, `lea.*`, GP-relative `lbgp/lhgp/lwgp/sbgp/shgp/swgp/addigp`) и **DSP**
(opcode `0x7f`: `minw/maxw/sclip32/add64/sub64/wexti/smar64/maddr32/msubr32/mulsr64/…`).
ABI с аппаратным float (обработчики сохраняют `f0–f31`) → 🟡 `ilp32f`. `gp = 0x106c18`, стек: вершина `0x140000`.

| Адрес | Регион |
|---|---|
| `0x00000000` | **код в RAM** (ITCM?): копия flash `0x48010a60`, длина `0x9baa`. **Смещение в файле = `0x10a60 + адрес`** ✅ |
| `0x00080000` | **boot-ROM** (функции, см. §4) |
| `0x00100000` | `.data` (копия с `0x4801a620`, `0x64b8` Б), затем `.bss` с `0x1064b8` до `~0x122000` ✅ |
| `0x0013ffff` | вершина стека |
| `0x10000000` | **PLIC** Andes: приоритеты `+0`, разрешения `+0x2000`, порог/claim `0x10200000/0x10200004` ✅ |
| `0x20000000…` | периферия (§5) |
| `0x48000000` | SPI-flash, XIP (секция CPU) |

Векторы: `mtvec = 0x48001500`, `mmisc_ctl.VEC_PLIC = 1` → это таблица адресов, `[0]` — исключения,
`[N]` — обработчик IRQ N. Каждый обработчик — обёртка (сохранить регистры → тело в RAM → `claim/complete` → `mret`). ✅

| IRQ | Тело | Блок |
|---|---|---|
| 3 | `0x5a84` | АЦП `0x21010000` |
| 8, 10, 11 | `0x2c8c`, `0x2f48`, `0x2d30` | `0x20010000` (🟡 захват/измерение частоты, I2S?) |
| 9 | `0x2d64` | `0x20020000/0x20170000` (🟡 аудио) |
| 21 | `0x46a4` | `0x20120000` (🟡 аудио/таймер) |
| 23 | `0x65c0` | `0x20170000` |
| 24 | `0x1498` | `0x20021000` |
| 32 | `0x9b58` | `0x20140000` |
| 34 | `0x8b10` | ❓ |
| 36 | `0x274c` | `0x20110000` (USB) |
| 22, 37 | пустые | — |

## 4. Boot-ROM `0x80000` (по вызовам из прошивки)

| Адрес | Функция | Аргументы |
|---|---|---|
| `0x80318` | memcpy | `(dst, src, n)` ✅ |
| `0x80410` | memset | `(dst, c, n)` ✅ |
| `0x8225e` | SPI-flash read | `(flash_off, buf, n)` ✅ |
| `0x82200` | SPI-flash write/program | `(flash_off, buf, n)` 🟡 |
| `0x8213c` | SPI-flash erase | `(flash_off, n, …)` 🟡 |
| `0x82356` / `0x8236e` | начало / конец операции с flash (`a0 = 0`) 🟡 |
| `*(0x80080)` | указатель на printf (строки: "device init complete!", "suspend", …) 🟡 |

Перед операциями с flash прошивка включает бит 24 в `0x20090000` (контроллер SPI) и ждёт бит 5 в `+8`.

| `0x21010000` | **АЦП**: старт по каналу, статус `+0x4c`, результаты `+0x50/0x54/0x6c/0x70` | ✅ |

## 6. Эмулятор `spv_emu.py`

**Ядро.** Класс `Emu(image)`. Интерпретатор с кешем декодированных инструкций flash, примерно 110 тыс. инстр/с.
Регистры `x[32]`, `f[32]` (сырые 32-бит), CSR в словаре, `trap()/mret` для исключений
(внешние прерывания **не генерируются**, PLIC не моделируется).
- Память: flash = образ по `0x48000000`; MMIO `0x20000000–0x22000000` → `mmio_read/mmio_write`; остальное — RAM,
  ленивые страницы по 4 КБ (`0x4c…`, `0x10000000` тоже попадают сюда как RAM).
- MMIO: значение = последнее записанное (`mmio_regs`). Хуки: `mmio_read_hooks[addr]`, `mmio_write_hooks[]`.
  Журнал `mmio_log` (отключается `log_mmio = False`).
- **Детектор опроса.** Если `(pc, addr)` читается больше `poll_limit = 2000` раз подряд без MMIO-записей между чтениями,
  ответ инвертируется навсегда (`poll_flips`). Так проходятся циклы ожидания «готово». Печатает `[poll] …` в stderr.
- **Время.** Каждое чтение `mcycle/time` прибавляет `cyc_per_read = 20000` тактов, поэтому задержки проходят быстро.
- `hooks[pc] = fn(emu)` — нативная замена функции (после вызова `pc = ra`). `pre_hooks[pc]` — вызов перед инструкцией.
  Вызов в диапазон ROM без хука → `unknown_rom` (если задан: лог и `a0 = 0`) или `Stop`.
- `hist` — последние 64 PC, `calls` — счётчик целей `jal/jalr ra`. Исключения: `Stop`, `Unimpl`.
- `dis(emu, start, end)` — дизассемблер с подстановкой GP-адресов.
- **Семантика Andes.** Проверены успешной загрузкой: `bbc/bbs/beqc/bnec/bfoz/bfos(msb≥lsb)/lea.*/lwgp/swgp/lbugp/lhugp/addigp/sbgp`,
  `minw/maxw/add64/wexti`. По спецификации P-ext, без проверки: `bfos/bfoz` при `msb < lsb`, `sclip32/uclip32`,
  `smar64/smsr64/umar64/umsr64/maddr32/msubr32/mulsr64/mulr64`, `ffb/ffzmism/ffmism/flmism`, `shgp`.
  Нераспознанный DSP-опкод → `Unimpl` с `f7/f3`. В `flash` (0x1000–0xe000) встречались ещё `f7` 0x00/0x10/0x1f/0x20/0x3f/0x4e/0x4f/0x50/0x6a/0x7f,
  но большая часть таких мест — данные, а не код.

**Обвязка `led_run.make(path)`.** Заглушки ROM, `0x20000000 = 0x49004080`, фиктивный ID кристалла,
`pre_hooks[0x13a4]` подставляет правильный ключ (обход проверки `0x1350–0x13cc`), журнал `gpio_log` для `0x20005000`/`0x21010000`.
```python
from led_run import make; from spv_emu import dis
e = make('firmware.bin'); e.run(2_500_000)     # ≈20 с, главный цикл 0x360 достигнут
print(dis(e, 0x360, 0x3a0))
e.store(0x106538, 4, 3)                         # «USB сконфигурирован» → заработает аудио-логика 0x1138
```
Снимок состояния: `copy.deepcopy(e)` после загрузки (так сделано в `spv_led_colors.emu_check`).

**Чего нет.** Модели USB-хоста (enumeration, HID-отчёты), PLIC/таймерных прерываний, аудио-DMA, реального АЦП.
Чтобы проверить код, зависящий от них, выставляйте переменные состояния в RAM вручную (см. §7) или пишите хуки.

## 7. Карта программы (RAM-код `0x0…`, flash-код `0x48…`)

**Старт:** `0x48000000 → 0xa4 → 0x480000b0` (sp) → `0x48001000` (gp, mtvec, CSR) → `0x480012e4`
(проверка второго образа `0x4c000000`) → `0x480068b0` (crt0: копирование RAM-кода/.data, bss) →
`0x48006b6c` init → инициализация в RAM-коде (тактирование, flash-конфиг, ключ, АЦП, аудио, USB) → главный цикл.

| Адрес | Функция |
|---|---|
| `0x360` | **главный цикл** (суперцикл): `0x1138` → LED (`0x5fc`, если LED включён) |
| `0x1138` | аудио-обработка, только при `[0x106538] ≥ 2` (USB сконфигурирован) |
| `0x12d4–0x13d4` | **проверка привязки к чипу**: ID кристалла (add64) XOR "Ttg?Tech" == flash `0x3e000`; иначе `0x588` |
| `0x588` | **перезагрузка в USB-загрузчик** (флаг в `0x2100801c`) |
| `0x5b9c` / `0x5b64` | задержки (по `mcycle`) |
| `0x4e18` | чтение конфига устройства (flash `0x38000`, 0xbc0 Б) |
| `0x5230` / `0x51a0` / `0x50ec` | загрузка / сохранение UI-настроек (`0x39bc0`) / упаковка из RAM-структуры |
| `0x21f8` | применение EQ-пресета (`[0x10648c]`) |
| `0x2430…` | громкость; на пределе → LED-событие 2 |
| `0x5988(ch, &out)` | чтение канала АЦП (ручки/кнопки) |
| `0x75f4` | стандартные USB-запросы (bRequest 0..11); `0x7888` = SET_CONFIGURATION → `[0x106538]` |
| `0x3a20…0x3e94` | запросы класса USB Audio (switch по ID блока `wIndex>>8`) |
| `0x74f8`, `0x8d84` | **HID vendor**: отчёт `[75, 1, 255]` → `0x588`; `[75, 1, n]` → подкоманды `0x8e90` (n = 1..4 …) ❓; `[75, 128, …]` ❓ |
| `0x9890` / `0x9818` | уход в сон (`wfi`) / подготовка пинов ко сну (пины 3, 34, 36 → выход 0) |
| `0x48004184` | `pwm_set(pin, en, duty)` |
| `0x48004288` | `led_set_rgb(r, g, b, on, brightness)` — R = пин 3 / ch3, G = пин 33 / ch1, B = пин 5 / ch5 |
| `0x48002fc0` | LED-режим `(mode, blink, period, counter)`: 0 белый, 1 зелёный, 2 красный, 3 синий, 5 фиолетовый |
| `0x5fc` | LED-задача по событию `[0x1064b8]` (см. `LED_findings.md`) |
| `0x48008b38` / `0x48008b5c` | GPIO: запись маски / направление пина |

**Переменные RAM:** `0x106538` — состояние USB · `0x10648c` — EQ-пресет (по умолчанию 8) ·
`0x1064b8` — LED-событие `{u8 ev; u8 blink; u16 counter@+2; u16 period@+4}` · `0x11cb10` — **UI-структура**
(`+15` = LED вкл, `+12` = пресет; соответствие полям файла см. в `0x50ec`) · `0x11cb34` — громкость/усиление.

UI-настройки по умолчанию (40 Б, записываются при пустой flash):
`02000000 ffffffff ff000000 ff010005 08000201 3c000100 ffffffff 01000001 00010100 0000ffff`.

HID-дескриптор (`0x48020a00`): Report ID **75** и **84**, по 63 Б in/out, Usage Page `0xFF01`; плюс consumer-клавиши громкости.

## 8. Как писать кастомный код (рецепт)

> **Теперь есть готовый путь: `sdk/` (C, gcc, крючки init/главного цикла, эмуляция).** Ниже — ручной способ для мелких патчей.
> `main()` прошивки: `0x48002d88 jalr ra,0xf4` (init) и цикл `0x48002d8c jalr ra,0x360`. `0x47f4` = частота ядра (360 МГц),
> `0x5b64(ms)` / `0x5b9c(us)` = задержки. RAM `0x122000…0x13f000` прошивкой не используется (замер в эмуляторе).

1. **Куда класть код.** Свободного места внутри CPU нет. Используйте область патчей flash `0x48020b94+`
   (после заглушек LED), расширяя `size` секции CPU в директории (`off 0x28`) и пересчитывая checksum
   (`Firmware.recompute_all()`). Байты `0x20ad4–0x20ae0` держите `0xFF`: на устройстве там стёртая flash,
   а crt0 копирует их в последний word `.data`. Не залезайте за `0x37000` (EXT).
2. **Как подключиться.** Замените `jal ra, F` (4 Б, ±1 МБ) на `jal ra, stub`, или в RAM-коде пару `auipc ra / jalr ra` на свою цель.
   Из заглушки выходите хвостовым `j F` (ra сохранён) или `ret`. Пример — `spv_led_colors.py`
   (`enc_jal/enc_auipc/enc_jalr/hi_lo`).
3. **RAM-код** (`0x0…0x9baa`) правится в файле по смещению `0x10a60 + адрес`. Он копируется при каждом старте.
4. **Сборка.** Toolchain в системе нет. Для мелких патчей кодируйте вручную (`enc_*`), для крупных —
   `riscv64-unknown-elf-gcc -march=rv32imafc -mabi=ilp32f -nostdlib -Ttext=0x48020ba0` → objcopy -O binary → вставить.
   Andes-инструкции в своём коде не нужны.
5. **Проверка.** Перед прошивкой всегда прогоняйте патченый образ в эмуляторе (`make(path).run(…)`, потом сценарий).
6. **Не трогайте** проверку ключа (`0x12d4…`) без нужды: при несовпадении устройство уходит в загрузчик (это обратимо).

## 9. Открытые вопросы / следующие шаги

- HID vendor-команды (`0x8d84`, подкоманды `0x8e90`): разобрать таблицу, найти команду «LED вкл/выкл» и
  команды, которые выставляют LED-события 1, 3–9 (из кода найдено только событие 2).
- Содержимое конфига `0x38000` (VID/PID/строки) — снять дампом с устройства.
- Секция EXT (`0x48037000`, 0x47 Б).
- Нужен ли второй образ `0x4c000000`; что делает загрузчик ROM с полем `encryptAddress`.
- Модель USB-хоста в эмуляторе (control-transfers через регистры `0x20110000`), чтобы гонять HID-команды.
- Сравнить `firmware.bin` и `firmware_prevc.bin` (48 188 разных байт): что изменилось между сборками.
- **На железе:** физическое соответствие пин → цвет, полярность LED, сохранённый EQ-пресет.

## 10. Аудио-тракт и кнопки (разобрано 2026-11-08, пример `sdk/examples/bubble`)

**Аудио через CPU.** USB ISO OUT обрабатывается в IRQ 34 (`0x8b20` → `0x7018`). Пакет кладётся в кольцевой буфер
`0x1066dc`, `0x6918` переводит в int32 L/R вперемешку, затем (если `[0x11c0bc] == 0`, т.е. не altsetting 4):
`>>2` (запас) → `0x9954` → **`0x1668(buf, frames, 10, fs)` = EQ** → `sclip32` до 30 бит → `<<2` → `0x696c` дальше к ЦАПу. ✅
- `0x1668`: выбирает таблицу коэффициентов по `fs` (44.1k `0x11c7dc`, 48k `0x11c714`, 88.2k `0x11c64c`, 96k `0x11c584`,
  176.4k `0x11c4bc`, 192k `0x11c3f4`, 352.8k `0x11c32c`, 384k `0x11c264`, 705.6k `0x11c19c`, 768k `0x11c0d4`; 20 Б на полосу)

- `[0x11cb34]` = fs в Гц, `[0x11cb38]` = разрядность (16/24/32).
- Обработчик IRQ сохраняет caller-saved f-регистры и fcsr и **включает вложенные прерывания** (`csrrsi mstatus,8`).
